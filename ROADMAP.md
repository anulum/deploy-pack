# Roadmap

Implemented local tooling validates repository metadata, maintained source and licence provenance, workflows, development dependencies, documentation and inventory through fixed command surfaces. It does not compose deployment packages or operate devices.

Planned composition resolves complete artifact roles, multiplicities, actual subjects, target and driver compatibility, required current gate verdicts and accepted trust context. Optional diagnostic failures stay visible and cannot satisfy required passing gates. Offline verification preserves actual freshness and validity limitations.

The intended public commands are compose, seal, verify, install, update, rollback and inspect, backed by one typed library. No domain command is installed here. A package is immutable and precedes later operation journals, capture segments, field judgments and assurance reviews; no future digest is inserted into earlier content.

Future per-unit operations require an actual authorized target provider, durable intent and separately observed result. Missing acknowledgment remains unknown until supported reconciliation. Automatic update requires independently accepted target recovery capability; unsupported targets remain manual-only. Cohort promotion requires the complete expected current health population and separate action authority.

Capture policy retains all three planned trigger modes, explicit units and complete source bindings. Existing fixed-interval numeric and composite-selector gaps need compatible source-owner reconciliation before runtime admission.

Completion requires full package and consumer integration, all original positive/refusal cases, genuine target observations for any advertised device capability, strict native checks, meaningful coverage, documentation and fresh comparison benchmarks for implemented counterparts. This source tree makes no deployment, recovery or signing qualification.
